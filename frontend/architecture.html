01 • Executive Blueprint

PulseFit Platform & Core Value Loop

PulseFit unites fragmented Indian endurance fitness into a self-reinforcing flywheel: athletic training logged on wearables generates verified points that subsidize event entry fees across official marathons, cyclothons, and brevets.

⌚

1. Wearable Ingestion

Strava Webhooks, Apple HealthKit, and Google Health Connect streams continuous pace, cadence, and biometric payloads.

REST / Webhook Gateway
🛡️

2. Anti-Fraud Gate

Heuristic speed cutoffs (>7.5 m/s running limit), heart rate/cadence cross-correlation, and GPS jitter algorithms reject motorized cheating.

Zero-Trust Heuristics
💎

3. Reward Ledger

Immutable double-entry balance credits 1 Pulse Point per 500m of verified activity. Points are non-falsifiable and audit-ready.

Double-Entry WAL DB
🗺️

4. Event Discovery

Autonomous AI sub-agents harvest Townscript, IndiaRunning, and Audax into a Leaflet Dark Matter Event Radar map with 1-click booking.

Sub-Agent Lakehouse
The Business Flywheel: Users run $\rightarrow$ Earn verifiable discount points $\rightarrow$ Register for marathons on PulseFit $\rightarrow$ Event organizers and sponsors fund the reward pool to acquire high-intent endurance athletes.

Anti-Bot & Anti-IP Blocking Defenses

  • Change Data Capture (CDC): SHA-256 fingerprinting checks if payload changed; skips re-crawling unchanged events.
  • Internal JSON APIs: Requests lightweight JSON backend endpoints instead of parsing heavy bot-protected web pages.
  • Headless CDP Fallback: Real browser contexts with real user-agent cookies only when Cloudflare challenges appear.
03 • Data Lakehouse

The Medallion Data Lakehouse Architecture

To ensure absolute data integrity and lineage, scraped data flows strictly through three validated tiers with an automated Dead Letter Queue (DLQ).

Layer Table Name Schema Contract Business Purpose
Bronze lakehouse_bronze { id, source, raw_payload, content_hash, crawled_at } Immutable raw payload archive; permanent ground truth.
Silver lakehouse_silver { title, city, venue, lat, lng, start_date, price_inr } Zod-validated, standardized dates, geocodes, and numeric prices.
Gold lakehouse_gold { canonical_slug, title, location, distance_tags, booking_urls } Deduplicated canonical event records served to production map.
DLQ lakehouse_dlq { source, raw_payload, error_code, quarantined_at } Quarantine for events missing mandatory fields or coordinates.
Entity Resolution Arbiter: Resolves multi-platform listings (e.g. Townscript + IndiaRunning for the same marathon) via a 3-pass matcher: Date ($\pm$24h) + Geohash radius (<25km), Jaro-Winkler string similarity, and merges multiple ticket booking URLs into a single canonical entry.
04 • Fraud & Trust

Biometric Wearable Validation Engine

Because points translate directly into financial event registration discounts, our zero-trust fraud engine inspects every uploaded workout for motorized pacing, GPS faking, or synthetic data.

🏎️

Velocity Threshold Cutoff

Rejects any run with average pace faster than Olympic sprint threshold (>7.5 m/s or 27 km/h) or cycling >18 m/s.

Strict Pace Filter
❤️

Biometric Cross-Correlation

Detects spoofing where cadence is 0 or heart rate does not elevate with speed, characteristic of motorized transport.

Sensor Fusion
📍

GPS Jitter & Deviation

Rejects mathematically uniform coordinate paths generated by desktop mock location generators.

Spatial Entropy
🔁

Stream Deduplication

Prevents double-claiming the same workout across multiple apps (e.g. Strava + Apple Health synced simultaneously).

Hash Matching
Audit Trail Guarantee: Fraudulent activities are never deleted; they are archived in the audit ledger with failure reason codes for dispute resolution and compliance.
